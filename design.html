Design for review · 29 October 2026

Video Production

An open, extensible agent skill that turns a brief and available assets into a reviewable video, with clear outputs, measured checks and practical recovery when production fails.

Agreed direction: broad video production from the first version, across industries, with clearly labeled support levels. The owner approved this design. A local version 0.1.0 candidate, helpers and original examples have been implemented; actual checks and remaining limits are recorded in docs/release-evidence.md.

1. What the skill promises

Help an agent understand the requested outcome, select a feasible production route, create the requested deliverables, validate them and explain remaining limits. It should work for product walkthroughs, training, education, marketing, presentations, social clips, case studies and narrative videos.

The reusable core handles production problems common to these fields. Industry knowledge comes from the user's sources and optional domain packs. It does not claim to solve every industry's business problems, guarantee cinematic quality or remove limitations of external generation models.

Public positioning: “From brief to reviewed video: plan, produce, check and revise with the tools you have.”

2. A short entry point with useful modes

Brief

Return a concise, self-contained production brief when the user asks for a prompt or plan. Read supplied material first. Ask only consequential unanswered questions; use declared defaults for routine choices.

Produce

Create actual media when rendering tools are available. For a substantial new video, propose a representative preview before the full render. Honor an explicit full-build request or an already approved style without reopening decisions.

Revise

Translate timestamped feedback into scene edits. Preserve approved scenes, narration and assets. Rebuild only changed segments and their dependent captions, transitions or mixes.

Diagnose and repair

Inspect a failed job or existing output, find the likely cause, perform bounded repairs and verify the result. Preserve usable work and report what could not be fixed.

Brief → capability check → representative preview → requested production → validation → delivery and revision

The workflow scales to the request. A five-second title edit does not trigger an interview or a minute-long preview. A requested preview ends at the agreed review checkpoint. Missing tools lead to an explicit blocker or an agreed alternative, never a claimed render that does not exist.

Each route records two independent things: maturity (tested, experimental, planned or unsupported) and availability here (ready, missing dependency, missing authorized access or blocked). A provider-dependent route can be tested elsewhere and still unavailable on the user's machine. A documented workflow is not a tested integration.

4. Production problems to address

ProblemConcrete response
Vague briefs and endless questionsExtract known requirements, surface only decisions that change the output, retain a concise accepted brief.
Wrong tool or missing accessCheck required capabilities before promising a render; disclose licensed/paid dependencies and meaningful fallback changes.
Weak story or inconsistent visualsUse a scene plan and shared style/character references, then assess a representative moving preview.
Robotic narration, incorrect names, caption driftCheck a voice sample, keep a pronunciation map, measure audio and align captions to actual speech.
Unreadable screens and poor cropsInspect the target aspect ratio and output size, preserve active controls and check caption placement.
Crashes, missing assets and repeated expenseSave scene/job state, track provider job IDs, cache reusable results and resume only verified work. Query uncertain paid jobs before submitting again.
Export defectsCheck streams, duration, resolution, decoding, audio and subtitle bounds; flag unexpected silence or black frames for review.
Unsupported claims and misleading resultsKeep facts traceable, distinguish actual footage from illustration, retain source and asset-rights records.
Expensive revisionsMap feedback to scene IDs and dependencies; regenerate only what the change invalidates.

Automatic checks establish technical properties, not beauty or factual correctness. Visual and listening review remain separate, and their actual scope must be reported. Model defects such as unstable faces or inaccurate lip sync may require bounded regeneration, a different approved method or an explicit unresolved result.

5. Clear outputs and reusable state

Use one project manifest as the canonical machine-readable record: requirements, scene IDs, assets/provenance, selected tools, timings, cost limits, generation job IDs, review decisions and validation evidence. Human-readable reports are derived from that record rather than competing copies.

  • Brief mode: concise brief and identified dependencies; no promised media file.
  • Preview mode: playable representative preview, script, captions when requested, and short quality/limitation notes.
  • Production mode: requested master/variants, requested captions, editable source, asset manifest and validation report.
  • Repair mode: repaired output when possible, evidence of the repair and clearly identified remaining problems.

Completion requires the requested artifact to exist and the stated checks to have run. Distinguish “rendered,” “technically checked,” “visually reviewed” and “user approved.” No opaque overall score should imply that all four happened.

6. Public package and contribution model

Use the open Agent Skills structure: a short SKILL.md, focused route references, executable helpers where they improve reliability, and examples. Keep host-specific integrations optional. Existing provider-maintained skills can supply tool details; this skill adds production coordination, consistent deliverables, review and recovery.

The proposed public repository also contains installation instructions, a support matrix, contribution guide, changelog, regression scenarios, asset credits and an MIT license for original code/instructions. Third-party tools and media retain their own licenses. The supplied builder document informs the design; do not redistribute its text without established permission.

Contributors may add a rendering route, provider adapter, industry pack, template or regression case. Each change must include a minimal example, documented dependencies and limits, and meaningful validation. Provider adapters declare supported inputs/outputs, duration/aspect limits, credentials interface, cost behavior, job polling, cancellation and retry semantics. Do not bundle secrets or rely on one user's local paths.

Prepare locally for publication. A public repository, upload or announcement requires a separate explicit publishing instruction.

7. First release and acceptance

  1. Test realistic baseline requests: brief-only, sample-first, direct full render, missing provider, failed render, uncertain paid job and an existing-video revision.
  2. Build the concise skill, shared manifest, capability check, validation helper and focused route references.
  3. Produce local examples covering a workflow recording, animated explanation and existing-footage edit. Use fictional or appropriately licensed assets.
  4. Run independent agent evaluations with the skill and compare observed behavior. Record failures and make targeted fixes.
  5. Validate package structure, links, actual example outputs, portability claims and secret-free distributable contents.
  6. Provide the local public-ready package and a release report. Mark external providers untested until genuine integration evidence exists.

Publication bar: a person can understand supported routes, install the skill, reproduce at least one documented example, locate clear outputs and submit a useful improvement. No support claim exceeds its recorded evidence.

8. Decisions proposed for approval

Working name: video-production. Broad production routes from day one; one tested local path before release; provider integrations added through a documented contract. Default to a representative preview for substantial new videos, with timing adapted to the request. Use a portable Agent Skills package, an original-code MIT license and public contribution guidance. Keep private GMC data, branding and machine paths out of the distributable.

Primary references checked

  • Agent Skills specification — package structure, metadata and progressive disclosure.
  • Remotion Agent Skills — existing provider-maintained creation, composition, rendering and caption guidance to build on.
  • FFprobe documentation — machine-readable media inspection.
  • FFmpeg filters documentation — editing/audio operations and diagnostic filters; their use does not establish subjective quality.
